# 稀疏 WebMercatorQuad 细分设计

英文设计稿是事实基准；本文是其中文翻译。

## 目标

消除“按层矩形细分窗口”造成的、可稳定复现的先细分再合并拓扑闪烁，同时保留
GeoScratch 有界、GPU 驱动的逆向 cover。

## 不变量

1. 每个描述符都是 OGC `WebMercatorQuad` 标准身份。
2. 细分决策绑定到精确父瓦片身份，并且只用该父瓦片自己的四个子瓦片替换它。
3. 子级决策只有在其祖先已被选择时才可到达。
4. 输出必须可见、确定、前缀无重叠、受容量约束且满足 2:1 邻接。
5. 相机派生的探查保持有界，不引入完整的世界根节点正向遍历。
6. Virtual Raster 与 atlas 驻留保持被动，不得改变几何 LoD。
7. CPU 参考实现与 WGSL 实现必须表达同一构造。

## GPU 构造

一次 compute 调用分两个互不重叠的阶段复用 cover lookup buffer。第一阶段把它作为
精确父瓦片身份的稀疏细分集合。每层沿用以相机为中心的有界探查窗口；高于最低层的
候选只有在其父瓦片已存在于集合中时才参与判定。第二阶段先生成可见的最低层 patch，
再逐层把命中的父瓦片替换为四个子瓦片。随后压缩不可见子瓦片，执行局部 2:1 闭包，
再次压缩，清空临时集合，并生成公开的最终 cover lookup。

## 失败语义

临时细分集合溢出、描述符溢出和最终 lookup 溢出都属于硬诊断。任何失败路径都不得
静默输出更粗的 cut。

## 验证

- 源码门禁禁止按层矩形合并细分决策；
- CPU 测试证明精确父子替换、前缀无重叠、确定性和 2:1 邻接；
- 代表性的俯视与倾斜视图必须满足 CPU/GPU 事实一致；
- 静止后的连续 pitch 扫描不得再出现无关条带整体合并；
- 着色与线框浏览器路径必须保持帧响应性和有界请求。
